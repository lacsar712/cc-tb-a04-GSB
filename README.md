# 茶叶拼配审评台

审评员对一个拼配批次打香气、滋味、汤色。服务端按 0.3 / 0.5 / 0.2 加权，7 分及以上通过。提交后只替换表格里新的一行，不整页跳转。

这是制茶审评，不是菜谱，也不是饮食记录。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3192 |
| 应用 | http://localhost:8192 |
| PostgreSQL | localhost:54392 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| taster | tea123456 | 可审评 |

## 启动

```bash
cd projects/13-tea-blend-cupping
docker compose up --build
```

## 盲评暗码

审评员在顶栏「暗码册」为批次生成六位暗码（`blind_codes` 记录真名、暗码、生成人、生成时刻）。

- 总表对观察员只显示暗码，不显示真批次名；审评员自己仍看真名。
- 观察员打开暗码册只能看到暗码一列；发码、改正真名仅审评员可操作。
- 改正真名会同步总表批次名，已发暗码保持不变。

## 验收

1. taster 登录后看到春茶-A 通过、夏茶-C 不通过。
2. 再提交一组高分，新行出现在表头，页面不整页刷新。
3. observer 登录后没有提交表单。
4. taster 给「春茶甲」发暗码后：observer 的总表看不到春茶甲字样、只能看到六位暗码；taster 的总表仍显示春茶甲。
5. observer 打开暗码册只见暗码列，不见真名、生成人、生成时刻。
6. taster 改正真名后，暗码不变，总表与暗码册均显示新真名，observer 侧仍只见暗码。
